## 底层控制全面审查（除视觉对接外）

### 🔴 严重（必修）

**1. `pos_deadband` 赋值不可达 —— 死区完全没生效**
`STM32F405.cpp:111` 是 `task.Init()`，里面 `vTaskStartScheduler()` **永不返回**；而 `:113-114` 的
`can1_motor[2].pos_deadband = 3.0f;` / `can1_motor[3].pos_deadband = 0.3f;` 在它**之后** ⇒ **永远不执行**。
实际死区 = 默认值 `0.0f`，即**小 yaw 和拨盘的位置死区全部失效**。
修：两行移到 `task.Init()` **之前**。（很可能与用户早先说的"拨弹轮发抖"直接相关）

**2. M6020 `maxspeed = 20` rpm 太小**（`motor.cpp:197`）
20 rpm = **120°/s**。这是 POS 内环速度给定的上限 ⇒ 小 yaw 最快只能 120°/s，转完 160° 行程要 1.33s。
手动模式名义给 180°/s（`yaw_rate = 8192×0.5`）也被这个内环压到 120°/s。
M6020 空载 320 rpm（1920°/s）。**建议提到 100~300**。

**3. M2006 `maxspeed = 3000` 远超实际**（`motor.cpp:203`）
M2006 空载仅几百 rpm，3000 是它的 6~10 倍 ⇒ 位置环输出 `speed_ref` 一有误差就顶到 3000
⇒ 速度环误差巨大 ⇒ `current` 饱和到 `maxcurrent = 10000` ⇒ **满电流狂转 → 过冲 → 反修 → 震荡**。
**这也指向"拨盘发抖"**。建议改到 **500~900**（实测稳态转速）。

### ⚠️ 中等（该改）

**4. `ControlTask` 用 `vTaskDelay(5)` 而非 `vTaskDelayUntil`**（`taskslist.cpp:138`）
周期 = 5ms + 执行时间，不定。`MotorUpdateTask`/`CanTransimtTask` 都用了 `vTaskDelayUntil`，只有 ControlTask 和 DecodeTask 没有。
受影响：`hold_ms += TICK`（TICK 硬编码 5）、`rate_ms`、`T_ARM = 300ms` 判连发、PID 的隐含 dt。

**5. `ArmTask` 同理用 `vTaskDelay(100)`**（`taskslist.cpp:164`）
2×`DMmotorinit`（各含 1ms delay）+ `power.Send()`（9600 波特率阻塞发送）⇒ 实际周期 ≈ 122ms+ ⇒ **上报实际约 8Hz 而非 10Hz**。

**6. 底盘逆解逐轮钳位会畸变方向**（`control.cpp:114-119`）
四轮各自 `clamp(w[i], ±5000)`。当 `|vx|+|vy|+|wz|` 超量程时四轮钳到不同值 ⇒ **合速度方向改变**（不是减速，是跑偏）。
全自动导航 vx/vy 吃满量程时极易触发。**建议改等比例缩放**：取 `max(|w[i]|)`，若 >5000 则全体同乘 `5000/max`。

**7. 达妙故障后无法自恢复**（`HTmotor.cpp:69-73`）
`DMmotorinit` 只发 `CMD_MOTOR_MODE`（0xFC 使能），从不发 `CMD_CLEAR_MODE`（0xFB 清错）。
`status`（0=Disabled/1=Enabled/8~E=过压·欠压·过流·MOS过温·线圈过温·通信丢失·过载）**存了但无人读**。
⇒ 一次过载/过温就永久失能，靠发使能帧恢复不了。全自动比赛里一次即废。
**建议**：ArmTask 里查 `status`，非 0/1 就先 0xFB 再 0xFC。

**8. CAN 接收的 `else` 分支太宽泛**（`can.cpp:144`）
所有非 `0x201~0x208` 的帧都进达妙分支，只靠 `Data[0] & 0x0F` 撞 `0x09`/`0x06` 来匹配 ⇒ 总线上任何别的设备/噪声撞上就会**污染达妙数据**。建议加仲裁 ID 白名单。

**9. 过温保护对 POS 模式电机失效**（`motor.cpp:85-87`）
`temperature > 70 → setspeed = 0`，但 POS 分支（小 yaw M6020、拨盘 M2006）根本不读 `setspeed` ⇒ **保护完全无效**。
且 C610 温度字节本机恒 0 ⇒ 拨盘连温度都读不到。建议 POS 分支也加温度检查（过温时冻结 `setangle`）。

**10. `initial_cnt` 是全局变量**（`motor.cpp:159-167`）
定义在文件作用域，**所有 Motor 实例共享** ⇒ `initial_x` 只有前 2 个电机被正确初始化，第 3 个起保持 0。
目前 `distance` 经 grep 确认**零消费者** ⇒ 现在无害；但做里程计时会立刻踩。建议改成成员变量。
