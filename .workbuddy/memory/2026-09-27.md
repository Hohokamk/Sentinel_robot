## 🔄 用户改架构（17:37）：**自瞄 yaw 走 M6020，不走达妙**

### 决定
"我们的 yaw 要走 m6020" —— 与上一轮我建议的"达妙 yaw"方案相反。

### 影响面（重大，主 yaw 通路整体换轨）
| 项 | 达妙 Yaw（原方案） | **M6020（新方案）** |
|---|---|---|
| `DMmotor[1]` 用途 | 自瞄 yaw | **退化为辅助/停用** |
| `yaw_speed_out` | 自瞄输出 | **没人消费**（`PANTILE::Update()` 那条 `setSpeed` 应删） |
| 控制类型 | 速度环（SPEED 模式） | **位置式**（POS 模式，`setangle`） |
| 角度反馈 | 需 IMU | **电机自带 `angle[now]` 单圈绝对角** ✓ |
| yaw 速率 | 不用了 | **`Control_Pantile` 那条 `+= -ch/660*4096*0.005` 必须早退**，否则和赋值打架 |
| 限幅 | 无（可 360°） | `ClampAngle(8096, ±1896)` ≈ **±83°，到不了全周** |

### ⚠️ 关键冲突 A：不可叠加（必须早退，不能简单跳过）
`Control_Pantile` 与 `OnPC` 都是 `setangle` 的写入方。`Control_Pantile` 的赋值在**条件内**（`if (y && y->has_feedback)`），但**函数尾巴的 `yaw_speed_out = ...` 是无条件的**。
AUTOAIM 下必须**整个 yaw 段早退**，例如 `if (ctrl.mode != CONTROL::AUTOAIM) { y->setangle += ...; }`。

### ⚠️ 关键冲突 B：速率型累加器当"位置型执行器" → 饱和与残值
`setangle += ch/660 * 4096 * 0.005`（满杆 ≈ 20.5 rad/s）是**理想速率积分器**，假设"电机瞬间到位"。换成"自瞄高频赋绝对角"后：
- 位置误差长期存在 ⇒ 累加器只增不减 ⇒ **冲到 ClampAngle 限幅边缘** ⇒ 手推到限位后**往回推有明显死区**，直到累加回程补完
- 不是纯粹的累加方向 bug，而是**架构不匹配**
- 修法：改**相对行程度量**：采集时记录 `enter = y->angle[now]`（或 `setangle`），映射为 `y->setangle = enter + (ch/660)*span` —— 天然有界、摇杆居中即原点、无死区

### ⚠️ 关键冲突 C：POS 分支 `setangle = angle[now]` 会在 latch 时**覆盖掉 `setangle` 的初值**
`control.cpp:47` `Init()` 里 `pantile_motor[YAW]->setangle = para.initial_yaw`（= 4096）**会被 POS latch 覆盖**（`motor.cpp:121` 的 `else setangle = angle[now];`）。
⇒ 遥操作冷启动瞬间，`setangle` 跳到当前机械角，之前推的摇杆量**凭空丢失**。
⇒ 且 `para.initial_yaw = 4096` 与 `ClampAngle` 的 `yaw_center = 8096` **语义不一致**（4096 会让初始化后 ClampAngle 把目标拉到 6200）

### 关键冲突 D：IMU 装在 M6020 控制的轴上
用户原话（09-27）"IMU 装在这个云台所控制的 yaw 上" → 这里的"这个"指的是**大 yaw（M6020）**，不是达妙。
⇒ **`Keep_Direction()` 该用 M6020 `angle[now]` 或 `imu_pantile.GetAngleYaw()`**（都不是达妙 yaw）。
⇒ 但 IMU 测的是**绝对朝向**，而 M6020 是大 yaw 之后的**次级** yaw → 两者关系需实测确认
