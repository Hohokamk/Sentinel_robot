### ⭐ 关键分水岭：两IMU 对比（2026-10-08 23:13→23:17 定位收敛）
**`imu_pantile`（UART5）帧头 = 90, 165 = `0x5A 0xA5` 正常；`imu_chassis`（USART3）帧头乱跳 + 大量全 0 帧。**
同一份代码、同波特率、同型号模块 ⇒ **解析层、波特率、协议全部排除，锁定 USART3 物理链路。**
⚠️ 用户"换了串口还是一样"—— 但要区分是**换物理位置**还是**只改代码绑定**；后者不动线，当然一样。
**现象判读（电气层典型特征）**：
- **帧头乱跳** = RX 线**浮空**（模块无供电/TX 未连/共地缺失），被环境干扰拾取
- **大量 `0x00` 帧** = 线被拉低或驱动无效（模块没供电 → TX 高阻；或 TX/RX 对调顶牛；或无共地无电流回路）
⇒ **这不是代码能修的。** 下一步是用 USB-TTL/逻辑分析仪直接接模块 TX 验证模块是否真的在吐`5A A5`（一击定论、零成本）。

**⚠️ crc 严重度修正（重要，别再按旧结论走）**：
CH010 主动连续输出下，每次都进 `if (帧头匹配)` 块 ⇒ `crc=0` **每帧都执行** ⇒ 进 `Check()` 时 crc 恒为 0 ⇒ **CRC 逻辑实际正确**。
只有「某帧帧头不匹配」时 crc 才会带脏值进下一次 Check ⇒ **丢一帧级别影响，非持续失败**。
⇒ **如果 UART5 帧头对但 `angle` 为 0，crc 不是原因**，应优先查上表 #2（CRC 字节序）和 #4（0x91）。

## 云台 yaw 通路：未通（阻塞自瞄联调）

**yaw = M6020**（`can1_motor[3]`，ID5，POS；`control.cpp:26` 按 `ID==ID5` 塞进 `PANTILE::TYPE::YAW`）。
**达妙 `DMmotor[1]`（0x06 SPEED）是死代码**，每周期仍在发 `0x206` 帧（`taskslist.cpp:111`）无人收。
⇒ **`xuc.yaw_diff` / `xuc.yaw` 从未流到 M6020 的 `setangle`**：
`RC_Control` 的 AUTOAIM 分支（`RC.cpp:142-146`）只写底盘；`RC::OnPC`（`RC.cpp:27-53`）只写 `mark_pitch` + 开火；
`Control_Pantile` 摇杆累加（`control.cpp:68`）在 AUTOAIM 下不执行；`ClampAngle`（`control.cpp:124`）只钳位不改值。
⇒ 云台 yaw 停在 latch 位，视觉偏差完全无效。

**写法约束**：只能用增量 `setangle += k*yaw_diff*22.756`（`8192/360`），**不能** `setangle = xuc.yaw`
（无 IMU 世界系参考，两系偏置未知）。增量天然 fail-safe：丢目标 → 增量 0 → 云台停。
**必配**：死区 0.3~0.5°、单帧限幅 ±5°、`k<1`（0.6 起步）。
⚠️ `ClampAngle` 每 5ms 跑，撞 ±1896 边界后被钉死而增量仍累加 ⇒ 表现为持续抽搐而非持续修正。
🔴 **动手前必须问视觉**：`xuc.cpp:36` `yaw_diff` **没转弧度**（同函数 `:37` 的 `pitch_diff` 转了）
⇒ 单位/正方向不确定则 `k` 纯猜。
