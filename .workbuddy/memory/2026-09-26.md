### 底盘硬件事实（用户提供）
- **四轮全向轮**（不是麦轮），**左前起顺时针编号 1 → 2 → 3 → 4**。
- 即：1=左前(FL)、2=右前(FR)、3=右后(RR)、4=左后(RL)。
- 对应关系：`chassis_motor[i]` = `can2_motor[i]` = 拨码 `i+1` = 电机编号 `i+1`（待上机核实）。

### 关键结论：45° X 布局下"全向轮"与"麦轮"逆解同构
独立推导验证（设半轴距 a、半轮距 b，轮心 r=(±a,±b)，驱动方向 d = ẑ×r̂ 切向）：
- d_FL = (1,−1)/√2、d_FR = (1,1)/√2、d_RL = (1,1)/√2、d_RR = (1,−1)/√2 → 与麦轮 X 布局相同
- 逆解矩阵秩 = 3 → **可全向**（用 (2,0,0)/(0,−2,−2c)/(0,0,2c) 三角化验证）
- 力矩独立验证：纯 vy 净力 (0,+2.83)、净力矩 0 ✓；纯 vx 净力 (+2.83,0)、净力矩 0 ✓；纯 ωz 净力 0、净力矩 4×127.3 ✓
- 结论：**K 的取值只影响自转速度手感，不影响"是否走直线/是否纯自转"**（vx/vy 列的力矩和恒为 0，与 K 无关）→ 先取 K=1.0

### 逆解公式（目标轮速，单位 = M3508 反馈的 rpm）
```
1 左前  w1 = vx − vy − K·ωz
2 右前  w2 = vx + vy + K·ωz
3 右后  w3 = vx − vy + K·ωz
4 左后  w4 = vx + vy − K·ωz
```

### 标定指纹（车架空先测"关系"，再落地测"整体方向"）
| 测试 | 期望关系 |
|---|---|
| T1 vx=1000 其余 0 | 4 轮**全同向** |
| T2 vy=1000 其余 0 | 1&3 同向、2&4 同向（**对角成对**），两组相反 |
| T3 ωz=1000 其余 0 | 1&4 同向、2&3 同向（**同侧成对**），两组相反 |

T2 与 T3 的分组方式不同（对角 vs 同侧）—— 这是布局指纹；若两者模式相同，说明轮子不是 45° 布局。
建议用集中符号数组 `const float sgn[4]` 修正，别把负号散落在公式里。

### ⚠️ 本轮发现的真实 bug：RESET 模式会被覆盖
`RC_Control()` 的 RESET 分支（`RC.cpp:135-149`）只写 `can2_motor[i].setspeed = 0`，**不清 `speedx/speedy/speedz`**。
而 `ControlTask`（`taskslist.cpp:132-135`）先跑 `chassis.Update()` 后跑 `rc.Update()` →
- cycle N：chassis.Update() 用**残留** speedx/speedy 写回 setspeed；rc.Update() 再清零 → 周期末为 0
- cycle N+1：chassis.Update() 又用残留值覆盖 → ...

而 `MotorUpdateTask`（2ms）与 `ControlTask`（5ms）无固定相位 → `Motor::Ontimer()` 会采到残留值 → **RESET 模式下底盘仍会以残留指令抖动输出**。
**修法（推荐）**：让 `CHASSIS::Update()` 成为 `chassis_motor[].setspeed` 的唯一写入方 —— 在它内部判 `ctrl.mode == RESET` 则输出 0，并删掉 `RC_Control()` 里那 4 行 `can2_motor[i].setspeed = 0`。

2. **反馈帧**：仲裁 ID = **MST_ID（默认 0）**；`Data[0] = status[7:4] ｜ motor_id[3:0]`；`Data[1:2]=POS`、`Data[3:4]=VEL`、`Data[5:6]=T`、`Data[6]=T_mos`、`Data[7]=T_rotor`。`status`：**0 = Disabled（上电默认）/ 1 = Enabled / 8~E = 过压·欠压·过流·MOS过温·线圈过温·通信丢失·过载**。
3. **问询式反馈**：电机只在收到控制帧之后才周期反馈 ⇒ **不使能也能收到反馈帧**（`CanTransimtTask` 一直在发控制帧），只是电机不出力。这是最安全的"纯接收"测试姿势。
4. 使能/失能/清错/存零 = 仲裁 ID `motor_id`，数据 `FF×7 + FC/FD/FB/FE`。

顺带核实了代码的解析是对的：`State_Decode` 的位切分（POS 16 位、VEL 12 位、T 12 位）与手册一致；ISR 用 `Data[0] & 0x0F` 匹配 motor_id 也正确。

### ⭐ 由此得出的关键结论：现有代码上车是天然安全的

`DMmotor[0].setSpeed` 在 latch 成功前**保持 0**（全局对象零初始化；`PANTILE::Update()` 里 `setSpeed = 1.5f` 那句写在 guard **内部**）→ POS_VEL 下限速 = 0 → 位置规划器不产生运动。

⇒ **即使反馈完全没进来、`setPos` 停在 `init_dm()` 写的 0，Pitch 也只会保持不动**。"朝电机零位转"这个之前反复担心的风险，在这套代码结构下不会发生。

⚠️ 这是**天然保护，不要误改** —— 若把 `setSpeed = 1.5f` 挪到 guard 外面（或给 `DMmotor[0].setSpeed` 填非 0 初值），这层保护立刻消失。

## 扳机设计：短拨单发 / 长拨连发（用户 2026-09-26 晚提出）

### 架构结论：模式 ≠ 扳机
- `ctrl.mode`（拨码）= **运动职责 + 是否允许开火**；**扳机是独立信号** = 什么时候拨弹。
- `FIRE` 保留 `openRub = true` 是对的 —— 语义变成**摩擦轮预转**（不打弹），这是必须的（否则首弹弹速不足）。
- ⚠️ **撤回上一轮建议**：`want_dial = openRub && 弹速达标` 就是用户否掉的"切进 FIRE 就开火"，必须再 `&& 扳机`。
- **框架原意证据**：`motor.h:59` `bool pd = 0, spinning = 0;//pd:单次拨弹 spinning:一秒八发` —— 原作者早设计过这两个标志，只是**零消费者**。ACE 模式是最终形态。

### 卡点：扳机信号源（6 个输入全被占）
ch[0]/ch[1] → 底盘；ch[2]/ch[3] → 云台；s[0]/s[1] 的 9 个组合**全部**映射到 mode。
→ 推荐 **`rc.pc.press_l`（鼠标左键）**：RM 标准做法，`RC.cpp:197` 已解析，一行可用；前提是图传/键鼠链路。
→ 摇杆当扳机要牺牲一个轴 + 加阈值迟滞；挪用 RESET 组合只能给电平、给不出长短。**都不满足需求。**

### 状态机关键决策：**按下瞬间即打第一发**（不等判长短）
- 短按 = 恰好 1 发，且**无"松手才出弹"的延迟**；长按 = 1 + N 发。
- 若反过来（先等 200ms 再决定），短按的发射时刻 = 松手时刻，手感差。
- 参数：`T_ARM = 200ms`（短/长分界）、`T_RATE = 100ms`（连发间隔；**SPD 版射频由拨盘转速决定，用不到 T_RATE**，只有离散步进版才需要）。
- 输出两个量：`fire_pulse`（上升沿，1 个周期）+ `fire_cont`（长按电平，`trig && hold_ms >= T_ARM`，**持续为真**）。

### 单发怎么"只出一发"（拨盘侧，两条路）

### ⚠️ 结构性障碍：现有 POS 分支对多圈失效（`motor.cpp:114`）
`float pos_error = (float)getdeltaa((int16_t)(setangle - angle[now]));` 三重失效：
1. `(int16_t)` 强转 → setangle 超 ±32767 回绕
2. `getdeltaa` → 归一到 ±4096（半圈）
3. `angle[now]` 是单圈值

**一发编码值**：拨盘 1 圈 = 转子 36 圈 = 294912；一发 = `294912/N`（N=每圈弹位数，N=8 → **36864**）。
数值推演：`setangle = A+36864` → `(int16_t)36864 = -28672` → `getdeltaa(-28672) = -20480`（只 +8192 一次）→ `mechanicalToDegree = -900°`。**期望 +1620°，方向反了。**

→ 拨盘必须走**累积基准** `sum_angle`（`int32_t`，`recorded_the_Laps()` 累积，零点 = 上电位置），误差直接相减、不做回绕归一。

### 修法：加 `bool use_sum_angle`，POS 分支分两路
`motor.h` 加 `bool use_sum_angle = false;`（public，装配处设）。latch 与误差各分两路：
```cpp
if (!angle_latched)
{
    if (use_sum_angle) { sum_angle = 0; angle[pre] = angle[now]; setangle = 0.f; }
    else                 setangle = angle[now];
    angle_latched = true;
}
float raw = use_sum_angle ? (setangle - (float)sum_angle)
                          : (float)getdeltaa((int16_t)(setangle - angle[now]));
```

### ⚠️⚠️ 陷阱：`angle[pre] = angle[now]` 那一行不能省
`sum_angle` 靠 `recorded_the_Laps()` 差分累积，而它在 mode 分支**之后**执行。零缓冲期间 `angle[now]=0` → 前 N 帧 delta=0、sum_angle=0。**真帧第一帧**：latch 时 sum_angle 还是 0 ✓，但紧接着 `recorded_the_Laps()` 算 `delta = 真值 - 0 = 3000` → `sum_angle = 3000` ✗ → **下一帧 pos_error = -3000，电机猛反冲**。
加 `angle[pre] = angle[now]` 让本帧 delta = 0 ✓（与公共尾段 `:132` 重复赋值，幂等）。

### ⚠️ 外环参数：`PID(0.30,0,0)` 纯 P → 末段爬行
一发 = 1620°（误差单位"度"）。`speed_ref = 0.30 × err`：err=1620° → 486rpm；162° → 48.6rpm；16° → 4.9rpm。
线性化 τ = 1/(Kp×6) = 0.56s → **一发约 3 秒**，太慢。要 125ms 一发需 Kp ≈ 3~6。
→ v1 先 `Kp = 3.0f` 实测；或给外环加"最小速度下限"（误差 > 阈值时 speed_ref 至少 ±min_rpm）。

### `SHOOTER::Update()`（POS 版）要点
- **驱动 `setangle`，不是 `setspeed`**（POS 分支不读 setspeed）
- **必须等 `has_feedback && angle_latched`** 才动 setangle —— 否则 latch 会把它清零

- POS 相对 SPD 的优势：**松开扳机后动作自己走完**（目标已设定）—— 这正是选它的理由

## 参数释义（同日 23:00）：`bullet_step` / `bullet_lead_max`，拨盘 N=8 → 7

### 定义与推导
- `bullet_step` = **一发弹对应的电机编码增量**。单位是**转子编码值**，因为 POS 双环的基准 `sum_angle` 就是转子计数累积（`recorded_the_Laps()` 逐帧累加 delta）。
- 编码链：C610 单圈 **8192** 计数（转子）→ M2006 减速比 **36**（`motor.h:9` `GEAR_RATIO`）→ **输出轴一圈 = 8192 × 36 = 294912** 转子计数。
- `bullet_step = 294912 / N`（N = 拨盘一圈弹位数）。
- `bullet_lead_max` = **允许"目标"超前"实际"的最大量**（防 windup）。判据在 `control.cpp:188-190`：`lead = setangle - sum_angle`，超了就钳回。原值 `73728 = 2 × 36864` → 语义 = **最多排队 2 发**。作用：卡弹时目标不会无限累积，解除后最多补送 2 发，而不是一次性把攒的量全放出来。
- 原 N=8：`36864` / `73728` ✓ 自洽（2 倍关系）。

### N=7 新值
| 量 | 值 |
|---|---|
| `bullet_step` | `294912 / 7 = 42130.2857` → **42130.29f** |
| `bullet_lead_max` | `2 × 42130.29` = **84260.57f** |
| 每发输出轴转角 | `360/7` = **51.43°**（原 45°） |
| 每发转子转角 | `51.43 × 36` = **1851.4°** = 5.1429 转子圈 |

294912 不是 7 的倍数（余 2）→ 一圈少 2 计数 = 0.0007%，可忽略；`setangle` 是 `float`，小数步长无碍。⚠️ 但 `sum_angle` 是 `int32_t`，别把 `bullet_step` 写进整型表达式。

### ⚠️ 连带①：lead 钳制只有单边
`control.cpp:189` 只钳 `lead > +bullet_lead_max`。若实际送弹方向使 `setangle` **递减**（lead 变负），保护**完全失效** → 卡弹解除后会一次性放出累积量。
→ 补对称钳制：`if (lead < -para.bullet_lead_max) d->setangle = (float)d->sum_angle - para.bullet_lead_max;`

### ⚠️ 连带②：单发 / 连发步长符号相反（上轮已提，仍在）
`control.cpp:179` 单发 `+= -bullet_step`，`:182` 连发 `+= +bullet_step` → 短拨与长按送弹方向相反。两条路径必须同号，符号由实际送弹方向决定。

### 射频红线（N=7 版）
- 8 发/s 需 `8 × 42130 = 337043` 计数/s = 41.1 转子圈/s = **2469 rpm**（M2006 `maxspeed = 3000` 的 82%）
- 纯满速上限 = `409600 / 42130` ≈ **9.7 发/s**；单发最短耗时 = `42130 / 409600` ≈ **103ms**
- 对比 N=8：8 发/s 只需 2160 rpm（72%）→ **N=7 对转速要求更高**，`lead` 更容易顶到钳位（属正常保护）

### 用户落地
`label.cpp:14-16`：`bullet_step = 42130.29f` / `bullet_lead_max = 84260.58f` / `dm_pitch_min = -0.60f` / `dm_pitch_max = +0.55f`（后两个是**占位值，未实测**）；`control.cpp:178/181` 单发与连发**已统一为 `-bullet_step`**（符号相反问题关闭）。

### ⚠️ 拨盘发抖：两个候选，靠"什么时候抖"分流

装配实读：`Motor(M2006, POS, supply, ID7, PID(20,0,0,0), PID(0.30,0,0,0))` —— 外环**纯 P**（`Kp=0.30`，无 D、无死区），内环 `current += pid[speed].Delta(...)`，`Kp=20`。

**候选 (a) 位置保持的 stick-slip 极限环**（最可能）
外环无死区 → 任何残余误差都产生非零 `speed_ref` → 弹簧压住拨爪的静摩擦把电机钉住 → 内环 `<br>`PID::Delta` 的**泄漏增量**（`pid.h:37-41`，`1.08*e - 0.92*e_prev`，`Ti=Td=0`）缓慢把 `current` 攒到能突破静摩擦 → 一动就过冲 → 误差反号 → 反向再来 → **抖**。
特征：**静止不拨弹时也抖**；`current` 缓慢爬升后翻转；`lead` 在 0 附近小幅摆动；`sum_angle` 微微来回。
修法：POS 分支加**位置死区**（`motor.h` 加 `float pos_deadband{}`，装配处按电机给值：拨盘 2~5°（转子度 = 输出 0.06~0.14°，可忽略）、M6020 0.2~0.5°），`if (fabsf(pos_error) < pos_deadband) pos_error = 0.f;`。
（`pos_error = 0` 连续两拍 ⇒ `Delta` 增量 = 0 ⇒ `current` 冻结 → 保力矩不抖。）

**候选 (b) 送弹方向与单向拨爪顶住**
本轮刚把单发/连发统一成 `-bullet_step`，若实际送弹方向为 `+`（或机构有单向拨爪）→ 位置环顶着挡块 → `current` 钉在 `maxcurrent = 10000` → 嗡嗡抖。
特征：**只在拨弹时抖**；`current` 顶 10000；`sum_angle` 几乎不动（或极慢）。
判别：手动把 `bullet_step` 反号试一次（一行），立刻顺畅即方向反。

⚠️ 若是 (b) 且已积累负 `lead`：**翻符号前必须先把 `setangle = sum_angle` 拉平**（或重新上电），否则一翻符号拨盘会把攒下的角度一次性冲出来。

### ⚠️ 连带：`lead` 钳制现在钳在"永远不会发生"的那一侧
`control.cpp:187-189` 只钳 `lead > +bullet_lead_max`，但步长已统一为**负** ⇒ `lead` 恒为负 ⇒ **该保护一次都不会触发**。卡弹时 `setangle` 会无界下降。
