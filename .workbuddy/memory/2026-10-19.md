## 🔴 一、协议文档与代码偏移不一致（今天最重要的发现）

给视觉写文档时逐字段核对`xuc.cpp` 的 `HandleAim()` / `HandleNav()` 实参，发现 `docs_通信协议.md` 写错了：

**`0x10` AIM_COMMAND（24 B）**

| 字段 | 旧文档（错） | 代码/新文档（权威） |
|---|---|---|
| flags | **@0(1B)** | **@14(1B)** ← 位置就错 |
| ref_epoch | @2 | **@4** |
| ref_seq | @4 | **@6** |
| ref_time | **@6(2B)** | **@8(4B)** ← 位宽也错 |
| valid_for_ms | @8(4B) | **@12(2B)** ← 位宽也错 |
| yaw_error | @12 | **@16** |
| pitch_error | @16 | **@20** |

**`0x11` NAV_COMMAND（24 B）**

| 字段 | 旧文档（错） | 代码/新文档（权威） |
|---|---|---|
| valid_for_ms | @4 | **@8** |
| flags | **@0** | **@10** |
| vx/vy/wz | @8/@12/@16 | **@12/@16/@20** |

### 为什么致命
- `ref_time` 只传 16 位 ⇒ `FindRef` 的四项全等匹配不上 ⇒ `last_reject = 3 (BAD_REFERENCE)`
- `flags` 位置错 ⇒ 读到 0 ⇒ `last_reject = 5 (INVALID_VALUE)`
- **两种情况都没有任何编译或运行报错**，视觉只会看到"自瞄不动"

### 机器校验（已做）
用Python 复刻 `R2/R4u/RF`，按新偏移构造 → 代码逐字段完全还原✅；
按旧偏移构造 → `ref_time` 解出 `0x00000000`（应 `0xDEADBEEF`）、`flags` 解出 `0x00`（应 `0x0F`）。

### 这是本项目第二次协议文档漂移
上次（10-15）：频率 10Hz/50Hz、CRC 口径、轴映射三处漂移。
**现象一致：文档是"写的时候对"的，代码后来又改了。**
⇒ **每次改完协议相关代码，必须同步核文档偏移。**

⚠️ 差点把带错偏移的文档发给视觉 —— **是"写完回头逐字段核对代码"这个动作救回来的，不是运气。**

## 五、方法论

1. **写完协议文档必须逐字段回核代码** —— 今天差点发出带错偏移的文档
2. **机器校验优于人工比对** —— 用Python 复刻解析函数、按文档构造、回读验证，比看表格可靠

4. **问对问题 > 设计实验** —— 用户一句"正方向是什么"比我设计的单轴旋转实验高效得多
