## 二、新需求：把**两个 IMU** 的数据都传给上位机 —— 分析

### 关键前提问题（必须先问视觉）
1. **只要 chassis 的 `yaw`，还是三个角都要？** 地面车体的 roll/pitch 近乎恒 0，若要"导航朝向"其实只需要 yaw；若他们要**积分做里程计**，那要的是 **gyro**，不是 euler
2. **`aim_x/y/z` 还要不要？** 这三格恒 0 且全工程无人写 ⇒ 决定能否**零长度变更**
3. **chassis 的 yaw 当"绝对世界朝向"用，还是相对量？** ⇒ 取决于模块是 **9 轴(AHRS)** 还是 **6 轴** 模式（`AT+MODE`）：9 轴的 yaw 是**磁北基准绝对航向**，两个模块理论应一致；6 轴的 yaw 会漂移，只能做相对量

### 三个方案
| 方案 | 做法 | 帧长 | 评价 |
|---|---|---|---|
| **D（首选）** | `aim_x/y/z` 三格让位给 `roll_c/pitch_c/yaw_c` | **32 不变** | ✅ 零长度变更 + 结构对称（两组 roll/pitch/yaw）+ 清掉死字段。`static_assert` 都不用改 |
| A′ | 只用 `aim_x` 一格装 `yaw_c` | 32 不变 | 最小，但只发 yaw |
| B | 帧尾追加 3 个 float（保留 aim_x/y/z） | 32 → 44 | 若视觉坚持要 aim_x/y/z |

**推荐 D**（若 aim_x/y/z 确认废弃）；B 作为退路。**不建议"复用 aim_x/y/z 但保留字段名"** —— 同名不同义会埋坑。

方案 D 的布局：
```
0     header 0x5A
1     flags(detect_color:1 | reset_tracker:1 | reserved:6)
2-5   roll_pantile(deg)   6-9   pitch_pantile(deg)   10-13 yaw_pantile(deg)
14-17 roll_chassis(deg)   18-21 pitch_chassis(deg)  22-25 yaw_chassis(deg)
26-27 rx_total            28-29 rx_count            30-31 CRC16
```

5. `tx_data[64]` 装得下 ✓
6. 🔴 `taskslist.cpp` 的 `Encode()` 调用条件放宽（导航模式也要发）

### 四个必须一起处理的隐患

2. ⚠️ **两个 IMU 的 yaw 零点独立**：绝对 yaw 不可比，**只有差值有意义**；若为 9 轴模式则都是磁北基准、可直接比 —— **必须跟视觉讲清是哪种**

## 五、两个 bug 的修法（教学，代码由用户敲）

### Bug ① `IMU::GetAcceleration()` 返回局部数组指针
```cpp
float* IMU::GetAcceleration() { float temp[3]{}; ...; return temp; }   // ❌ 悬垂指针 UB
```
`temp` 在栈上，函数返回即失效 ⇒ 调用者拿到垃圾（会被后续函数调用覆盖）。
**推荐修法**：加三个 public getter，与 `GetAngleRoll/Pitch/Yaw` 风格一致
```cpp
float GetAccX() { return acceleration.x; }   // 同理 Y / Z
```
备选：`void GetAcceleration(float* out)` 写入调用者数组。
⚠️ **不要用 `static float temp[3]`** —— 消除 UB 但引入共享可变状态，多次调用互相踩。

### Bug ② `angularvelocity` 只有一个 getter，且命名不规范
```cpp
float getangularvelocitypitch();   // 只有 pitch；roll/yaw 无接口
```
**修法**：补三个规范命名的 getter（`GetGyroRoll/Pitch/Yaw`），删掉旧的那个（零消费者）。
⚠️ **单位提醒：`0x91` 包的 gyro 单位是 `deg/s`，不是 rad/s**（与欧拉角的 deg 同族）。视觉若要积分必须知道。
⚠️ `imu.cpp` 的 gyro 与欧拉角**同样存在 X↔Y 交换**（24→pitch、28→roll），同属"疑似 90° 安装补偿"，**待实机单绕一轴验证**。

## 六、12 个数据的帧容量分析

- **带宽完全不是瓶颈**：921600 baud ÷ 10 bit ≈ **92160 B/s**；最坏情况 80B × 10Hz = 800 B/s = **0.87%**
- **真正的两个约束**：
  1. `tx_data[64]` **装不下**（最坏 80B）→ 必须放大到 96
  2. 🔴 **10 Hz 上报率对角速度/加速度毫无意义** —— 做不了积分、做不了动态检测。**若要 gyro/acc，上报率必须提到 100~200 Hz**
- **上行率提升路径**：`Encode()` 从 `ArmTask`(100ms) 挪进 `DecodeTask`(5ms) → 200 Hz
  - ⚠️ `DMATransmit` **不检查上一次是否发完**（直接 DISABLE → 重装 NDTR/M0AR → ENABLE）⇒ 高帧率下会**打断在途帧、发出半截包**。80B@921600 需 0.87ms，5ms 周期安全；**1ms 周期会撞。建议在 `DMATransmit` 里加完成检查**
  - ⚠️ `DecodeTask` 用 `vTaskDelay(5)` 非 `Until` ⇒ 实际略低于 200 Hz

### 推荐布局：80 字节，两个**对称的 9-float 块**
```
0     header 0x5A
1     flags(detect_color:1 | reset_tracker:1 | reserved:6)
2-37    IMU-P 块：euler(3) + gyro(3) + acc(3) = 9 float
38-73   IMU-C 块：euler(3) + gyro(3) + acc(3) = 9 float
74-75   rx_total
76-77   rx_count
78-79   CRC16
```
**核心优点**：两块结构完全对称 ⇒ 视觉侧只需写**一个** `ParseImuBlock(p)` 函数，两块共用；以后加字段只改一处。**帧结构一次冻结，不用来回同步。** 现在欧拉角填真值，gyro/acc 先填 0，等视觉确认后"填值"即可、**不动结构**。

改动清单：`TxPacket` 重排 + `static_assert` → 80 + `tx_data[64]` → `tx_data[96]`（建议）+ `Encode()` 填字段 + `AppendCRC16CheckSum` 自动跟 `packet_size` ✓ 不用改。⚠️ **`XUC_FRAME_LEN`(=40) 是下行帧长，不要动。**

## 七、🔴 AUTO 模式进不去的**根因定位**（18:45，一行代码）

**根因：`control.h:18` 的 `enum MODE { PC, RC, AUTO, ... } mode;` 没有给初值。**
`RC rc;` / `CONTROL ctrl;` 都是全局对象 ⇒ **零初始化 ⇒ `mode = PC = 0`**（`PC` 是枚举第一个）。

而遥控器不开时：`rc.s[0]=rc.s[1]=0`（`enum POSITION { UP=1, DOWN, MID }` ⇒ `RC_STATE(0,0)=0` **不匹配任何 case**）⇒ `RC_CheckState()` 落 `default:` **什么都不做** ⇒ **`ctrl.mode` 永远停在 `PC`**。
⇒ `OnPC()` 第一行 `if (ctrl.mode != CONTROL::AUTO) return;` ⇒ **视觉指令全部被挡，车一步不动**。

**修法（一行）**：
```cpp
enum MODE { PC, RC, AUTO, RESET, ROTATION, SPINNING, FOLLOW, SEPARATE, FIRE, STOP, LOCK } mode = AUTO;
```

**为什么安全**：上电 `pc_timeout = 0`、`last_rx_count = xuc.rx_count = 0` ⇒ `OnPC()` 一直走**失联分支**（清底盘 + 停摩擦轮 + 停火）⇒ **视觉没发数据之前车不会动** ✓
（追踪：`if (rx_count != last_rx_count) { last_rx_count = rx_count; pc_timeout = TIMEOUT_TICKS; } else if (pc_timeout > 0) --pc_timeout;` → `if (pc_timeout == 0) {...清...; return;}`）

**两个加固**：
1. `last_rc_tick == 0`（**从未收到过遥控帧**）也应判失联 —— 现在上电头 100ms 会被误判成"遥控在线"：
   `const bool rc_lost = (last_rc_tick == 0) || ((xTaskGetTickCount() - last_rc_tick) > pdMS_TO_TICKS(RC_LOST_MS));`
2. （可选）`RC_CheckState()` 开头 `if (rc_lost) return;` —— 防"遥控曾在中位、突然失联"把 mode 锁死在手动模式
3. （可选，**不推荐**）遥控失联且视觉在发数据 ⇒ 强制回 AUTO。会打断调试（在 FIRE 模式测时视觉一跑就跳走）

**验证**：① 不开遥控器上电 → watch `ctrl.mode` 应为 `AUTO`(值 2) ② 视觉发一帧 → `pc_timeout` 跳 50、底盘响应 ③ 停视觉 250ms → 底盘+摩擦轮停 ④ 开遥控器拨到 SEPARATE → mode 切走、视觉失效 ✓

**操作提醒**：改完后「遥控器不开 = 全自动；遥控器一开 = 拨杆是唯一主人」。比赛时要么彻底不开，要么把拨杆锁在 UP/UP。**写进赛前检查表。**
⚠️ 另：拨杆在 UP/UP（AUTO 位）时若视觉失联，`OnPC()` 会清底盘 ⇒ **摇杆也没用**，想手动挪车必须拨到别的模式。逻辑自洽但需知情。

**已完成**：`AUTOAIM → AUTO` 改名彻底（`taskslist.cpp` 的 `if (ctrl.mode == CONTROL::AUTO) xuc.Encode();` 已同步，全工程无 `AUTOAIM` 残留）。git 未提交：`RC.cpp` / `STM32F405.cpp` / `control.h` / `taskslist.cpp`。

## 九、视觉 IMU 需求（10-11 晚）→ 定稿上行 **64B** 布局

**视觉原话需求**：
- 云台 IMU：姿态 roll/pitch/yaw + 角速度 gx/gy/gz + **采样时间戳** + **传感器身份** + **数据有效标志**
- 底盘 IMU：姿态 roll/pitch/yaw + **采样时间戳** + **传感器身份** + **数据有效标志**（**无角速度**）
- 要求写清：**单位 / 旋转顺序 / 参考系 / 正方向**
- **每个 IMU 独立记录时间**，**云台有效标志分开设置**
- 姿态有效 = 初始化完成 ∧ 近期收到有效数据 ∧ 数值正常 ∧ 无已知故障

**⇒ 推翻了早先的 80B 对称方案**（视觉明确底盘不要 gyro）。改为 **64B**，两块不对称。

### 帧布局（`sizeof(TxPacket)=64`，每 float/u32 落 4 的倍数偏移）
`0`hdr 0x5A｜`1`flags｜`2-3`rsv0｜`4-27`**云台块**(roll,pitch,yaw,gx,gy,gz · float)｜`28-31`p_time(u32 ms)｜`32`p_id｜`33`p_valid｜`34-35`rsv1｜`36-47`**底盘块**(roll,pitch,yaw)｜`48-51`c_time｜`52`c_id｜`53`c_valid｜`54-55`rsv2｜`56-57`rx_total｜`58-59`rx_count｜`60-61`rsv3｜`62-63`**CRC**
🔴 **CRC 必须恒在末两字节** ⇒ 对齐填充只能放 CRC **之前**；放后面会让 `AppendCRC16CheckSum(len-2)` 算错。
✨ **对齐设计红利**：布局在有无 `packed` 下**完全一致** ⇒ 一次性规避 MSVC 忽略 packed 的整帧错位（即此前 32→36 那个坑）。

### 数据源（要新增的代码）
- **时间戳**：`0x91` **offset 8 `system_time`**(u32，ms，模块上电起累加，24h 回绕) —— 官方字段表确认存在。`U4(rxData + offset + 8)`；加成员 + `GetTimestamp()`
- **传感器身份**：不依赖包内 ID（Sea Land 手册说 byte1=ID，超核中文手册说 1-2 是 pps_sync_stamp，版本有出入）⇒ **装配处给常量**：`imu_pantile.id=1`、`imu_chassis.id=2`
- **有效标志**：`IsValid()` = `init_done && (tick - last_rx_tick) <= 50ms && 数据在量程内`。`last_rx_tick` **只在 CRC 通过那一帧**刷新；NaN/Inf 用 `fabsf(v) <= 180` 天然拦掉（NaN 比较恒 false）
- 角速度：`GetGyroRoll/Pitch/Yaw()` **已补好** ✓；`GetAccX/Y/Z()` 已有，但**本帧不上传加速度**

### 姿态口径（写进协议文档 §6.2 给视觉）
- 单位 **deg**；角速度 **deg/s**
- 参考系：body 相对世界系；世界系零点由 `CONFIG IMU COORD` 决定
- 旋转顺序：**ENU→312(Z-X-Y)** / **NWU→321(Z-Y-X)** ⚠️ 待确认模块配置
- 正方向：右手系，roll 绕 X / pitch 绕 Y / yaw 绕 Z，yaw 逆时针为正(ENU)，±180°
- yaw 基准：**9 轴=磁北**、**6 轴=上电初始朝向(会漂)** ⚠️ 待确认模式

### 待视觉确认（新增）
① ENU/NWU（决定旋转顺序）② 6 轴/9 轴（决定 yaw 基准）③ 时间戳用模块 `system_time` 还是 MCU tick ④ id 用常量 1/2 可否 ⑤ **是否要加速度**（要则需再扩帧 = 又一次断链级变更，**建议一次问清**）⑥ 角速度若用于**积分**，10Hz 不够（需 100~200Hz ⇒ Encode 挪进 DecodeTask + 给 DMATransmit 补完成检查）

**清理项**：`imu.h` 残留死声明 `GetAcceleration()` / `getangularvelocitypitch()`（定义已删）应一并删掉。

### Encode() 落地要点（10-11 晚补充）
- 函数体 = 纯搬运：两块各 9/6 行 getter 赋值 + `rx_total/rx_count` + memcpy/CRC/DMATransmit，**结构照旧**，只是字段名从 `roll/pitch/yaw/aim_*` 换成 `p_*/c_*`
- ⚠️ **旧的 6 行（`TxNuc.roll/pitch/yaw` + `aim_x/y/z`）必须删掉**，否则字段已不存在 ⇒ 编译报错
- 🔴 **`imu.cpp` 需要 `#include <math.h>`**（新增的 `fabsf` 量程检查用到；imu.cpp 目前只 include 了 `imu.h`/`label.h`，没有数学头）
- `TxNuc.checksum = 0;` 其实**可留可不留** —— CRC 覆盖 `[0..61]`，`[62..63]` 不在覆盖内，`AppendCRC16CheckSum` 会直接覆写它
